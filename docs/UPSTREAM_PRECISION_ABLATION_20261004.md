# 上游精度与速度取舍：2026-10-04

## 结论

可以保留一部分 Prefill / 首字延迟收益，并在本轮测试中维持旧版数值行为。建议采用精度优先组合继续验证；当前全开组合不适合作为日常 Harness 工具任务的默认升级。没有证明通用任务准确率下降，也没有证明新数值近似完全无损。

精度优先组合保留 MoE up+mid 融合、multi-tile，关闭 FP16 index、FP16 pairs、Dense WMMA 和 split-K。它保留的是既有 hybrid 精度策略，不是切换到全 FP32 或原始 BF16 模型。权重未重新量化。

## 逐项开关对照

每个单项均在精度优先组合上只开启该项；全开开启全部新增选项。下表速度是单次筛选结果，仅用于解释取舍，不能替代上述 A/B/B/A 复核。数值检查使用同一 8K 自然文档、4095 个评分位置，与旧版输出分布比较。

| 组合 | 2K TTFT 减少 | 8K TTFT 减少 | 平均 KLD | 首选 token 一致率 | PPL |
|:---|---:|---:|---:|---:|---:|
| 旧版 | +0.00% | +0.00% | 0.000000 | 99.976% | 10.879714 |
| 精度优先 | +1.68% | +2.19% | 0.000000 | 99.976% | 10.879714 |
| 仅加 FP16 pairs | +2.50% | +4.61% | 0.008525 | 94.872% | 10.834834 |
| 仅加 FP16 index | +2.24% | +2.49% | 0.007307 | 95.482% | 10.849995 |
| 仅加 Dense WMMA | +15.80% | +4.82% | 0.007396 | 94.994% | 10.865439 |
| 仅加 split-K | +1.18% | +1.01% | 0.008643 | 94.921% | 10.869534 |
| 全部开启 | +19.01% | +8.48% | 0.008604 | 95.043% | 10.860266 |

- 精度优先的自然文档 PPL、KLD 汇总与旧版重放一致；参考使用压缩 logprob，旧版本身首选 token 一致率为 99.976%，不是严格的 100%。
- 其他单项均改变分布；PPL 没有恶化。首选 token 的差异率不是任务准确率下降比例，离旧版更近也不等于离原始模型更近。
- 各项 KLD 不能相加；非线性传播与路由、舍入相互作用使组合结果不同。FP16 pairs/index 降低中间表示精度；WMMA 改变计算路径；split-K 改变累加顺序。
- index/split-K 在两个合成速度提示上生成结果仍相同，但在自然语料的分布检查中存在偏差。因此仅凭生成文本相同不足以宣称无数值变化。

补充短混合语料（2040 个评分位置、同一量化模型的既有 exact-path 参考）：

- 旧版：mean KLD 0.027064，PPL 2.915944，首选 token 一致率 96.275%。
- 精度优先：mean KLD 0.027064，PPL 2.915944，首选 token 一致率 96.275%。

这里没有原始 BF16 模型质量金标准。未检测到新增误差的结论限于本轮语料、生成与任务；不宣称任意输入逐位等价。

原始故障复现导致的测试失败单独计数，不算修复回退；完整检查项、隐藏测试结果、工具动作摘要和请求哈希在 JSON 中。

旧版台账中 Prefill 约占总时间 14.7%，代码任务约 4.3%。若其他行为完全不变，Prefill 耗时减少 8% 对完整任务的直接影响约为 1.2% 和 0.34%；若 Prefill 耗时仅减少 2%，约为 0.29% 和 0.09%。这些是耗时占比估算，不是新任务性能保证。上轮全开台账快 6.69%、代码慢 9.71%，主要还受生成长度、规划和额外轮次影响。

因此，对当前可靠工具执行/代码工作负载，优先保留旧版数值策略。全开多省下的首字等待尚不足以证明值得承担额外数值不确定性；它可保留作延迟优先的实验选项，但需要更多真实 Harness 成功率与完整耗时数据。不能把“更快 Prefill”直接等同于“更好用”。
