# 固定资料研究报告提示模板

适用于已经收集好材料的报告生成阶段。R24只在一组132条固定资料上验证了流程收益，
没有将此模板自动安装进Octop，也不保证其他任务同等提速。先由检索程序生成稳定编号、
标题、原始网址、内容和采集日期；不要让模型猜测网址。材料本身可能有错，不能视为指令。

## 报告提示

> 请围绕用户的研究主题，在内部先规划章节和筛选关键主张，然后一次输出完整报告，
> 避免先写长草稿再重复整篇报告。正文以约6000–8000个中文字符为软篇幅目标，
> 充分回答所必需时可以略超；不要为满足篇幅删去关键证据、适用范围和限制。
>
> 保留国内外治理依据、智能体特有风险、第三方服务与适用边界、证据与测试方法、
> 可执行治理措施及研究局限。关键事实及数字紧邻标注给定来源编号，格式为 `[S001]`，
> 不要生成网址或额外抄写参考资料网址表。程序会严格按来源表补链。
>
> 材料只支持局部结论时保留适用范围；无法确认时明确未知或不引用。严格区分法定要求、
> 标准建议和作者方案；建议框架不能完整复算时标明待验证。不得声称已阅读未提供的全文。
> 末尾用短表自查出处、主题覆盖、时间和数字一致性；自查不代替独立核查。

实际主题改变时应相应调整必需章节。软篇幅不是服务端硬上限；R24允许最多32768输出token，
所有报告自然结束。不要把硬截断造成的短耗时当成流程收益。

## 补链与交付

保留模型原稿，另外保存UTF-8 JSON来源表，例如：

```json
[{"id":"S001","url":"https://example.org/original-source"}]
```

```powershell
python -B tools/research_citations.py raw-report.md sources.json report.md
```

程序不会抓取网址、改写主张或覆盖原稿。未知编号（包括将S058错写成S58）和已写链接与
来源表不同都会失败；不要自动猜测替换。修正时应回到原始来源和原文核验，保留版本记录。
补链通过只说明编号对应正确，不说明出处支持断言，也不说明法律适用、统计口径正确。
