# R17：真实负载、数据流与核心算子探索


## 结果概览

四个方向均完成实现或探针、验证和取舍。本轮可确认的交付是两个默认关闭的 QSA 实验开关，以及工具调用错误分类修复。没有获得跨输入长度稳定的整体加速，也没有采用降低精度来换速度。

仅相邻 head 调度在 128K 输入的两次完整请求中均更快，分别减少 0.98% 和 3.02%；短输入结果混合。单独 KV 融合及组合方案未形成稳定的普遍收益，未推为默认。

## 本轮范围与判断标准

本轮覆盖专家计算/QSA/GDN/请求链路四个方向，每个方向都落实为代码或实验，并给出处置结论。完成本轮探索不等于穷尽该硬件与模型的所有优化可能。

环境为 Windows 11、Ryzen AI Max+ 395、Radeon 8060S、128 GiB 统一内存。起点为 Fork 的 `039103eef0df549eab1ad5b12715c35e0c44db96`（R16c）；引擎比较使用同一个 R17 二进制的开关对照，未更改或重新量化 v2 主权重与 PLE sidecar。不是与最新上游旧格式模型重新进行排名。

整模型测试固定 grouped/native HT、BF16 KV、单槽位、262144 上下文容量、8192 Prefill 分块、greedy、关闭思考、MTP gamma=2。普通计时固定大 FP32 indexer 投影为 `-711`，不启用 profiler/audit。实际输入为 9217、32768、131072 token，输出固定 128 token；容量 262144 不等于已测满 256K。开关默认关闭。

所有 GPU 实验串行执行。临时实例由独立 owner 记录 PID、启动时间、路径及配置身份，并在结束后清理、恢复隔离配置。未修改日常部署、Octop 配置或模型文件。

## 专家计算：真实路由分布与小 tile 分流

在模型中捕获 48 层、3 个分块位置的 144 组真实路由。提示词是固定的台账/代码/JSON/事件混合合成文本；“真实”指模型实际产生的路由，不是用户原始业务 Excel。每组 8192 token，每 token 选 10 个专家。

活跃专家为 330–505/512；最忙专家接收 1085–8192 个 token；前十专家占分配量的 11.53%–53.73%。BN64 的尾部补齐槽位占 15.06%–20.15%。补齐槽位比例不是可直接兑现的运行时间占比。

从低/中/高离散度路由中选取 3 个代表，比较原 BN64、全 BN32、短 tile 使用 BN32+其余 BN64、再加 R16 双缓冲。另测两个边界分布。先用实际计数与随机 token 映射，再补做实际专家-token 成员关系的回放；后者按专家内 token 顺序规范化，不声称复现原 GPU 原子排队次序。权重与激活采用受控随机值，并非模型的完整专家张量转储。

计数回放中全 BN32 慢约 6%–7%；混合分流慢约 0.48%–0.74%。补测实际专家-token 成员关系后，全 BN32 慢 6.06%–6.68%，混合分流慢 1.15%–1.53%，与 R16 双缓冲一起用则只快 0.30%–1.01%。叠加 R16 双缓冲的一点局部收益不能归给新分流，而且未包含分流列表的构建成本。比较均检查逐位输出、有限值、前后 guard 与只读输入。新分流不进入生产默认路径。

## QSA：访存顺序与 KV 准备融合

捕获两个实际层的 Q、K、V、转置 V、选块索引和页表，测试 256/2048/8192 行。相邻 token 的选块集合平均重合 71.94% 与 46.15%；这是集合交集，不是硬件 L2 命中率。

实现四种独立组合：原路径、重排相邻 KV head 的 CTA 调度、在 LDS 预计算物理块地址、两者组合。两个独立微测试进程、每形状十轮轮换计时中，相邻 head 调度局部耗时减少约 10.6%–18.2%，输出逐位一致；LDS 地址缓存没有稳定收益，不接入。未采集硬件缓存计数器，不能把具体提速机制当成已证实的 cache-hit 结论。

KV 准备改动直接把同一 FP32 K 结果按页表写入 BF16 缓存，并让 V 的一次转换同时写行主序和块转置布局。保持原归一化树、RoPE、FP32 K scratch 和 BF16 RNE 舍入。保护首个部分块已有槽位、清零尾部无效槽位，保留其他路径回退。

72 个连续/置换页表、页洞、非对齐 base 和尾部用例全部逐位一致。四个局部计时形状减少 6.69%–45.60%，但该阶段很短：连续页表 P=8192 时约 0.452→0.421 ms，不能按百分比推成整模型收益。

新增 `GDEC_QSA_HEAD_INTERLEAVE=1` 与 `GDEC_QSA_KV_FUSED=1`，仅用于符合条件的 paged BF16 QSA 路径；都默认关闭。组合是否有整体收益见完整请求表，不能把各自微核百分比相加。

## GDN：分块扫描与两投影共调度

扫描 32 个投影形状：P=1024/1025/1536/2048/3072/4096/8191/8192，N=10240/6144/2560/12288（前三种对应当前 GDN，12288 为扩展探针），各测 GM=1/2/4/8/16。各候选输出逐位一致，但不存在跨形状都更快的单一替代。GM16 在一些 P=1025 形状有 3.9%–14.7% 的局部收益，在大块或 output projection 上则退步；不据此对单个边界过拟合默认规则。

进一步实现 QKV 与 Z 两套权重、两块输出的共同调度，保持各列原 WMMA 累加顺序，不复制拼接权重。8 个 P 形状、5 个候选均逐位一致。GM4 在中小形状的局部收益不稳定，常用 P=8191/8192 略慢约 0.20%/0.10%，没有进入整模型默认路径。其余 GM 的退步一并保留。

## 请求链路：错误分类与真实工具任务

修复正常停止后的未知/未完成工具调用被标为 `length` 的问题。Chat 返回明确的 `invalid_tool_call`；SSE 已发送响应头时使用错误帧；Responses 返回 `failed` / `response.failed`。真实输出预算耗尽仍是 length/incomplete。不会猜测工具名或编造参数，也不宣称实现了完整 JSON Schema 约束解码。

CPU 测试覆盖 Chat/Responses、JSON/SSE、有效调用、未知工具、缺少必填字段、未闭合调用、真实 length、普通文本、先有效后无效的混合调用，共 28 个组合；另跑完整 API 回归与断连取消回归。客户端应等待完整响应成功结束再执行工具，不能在收到半段调用时就假定成功。

实际 Agent 用隔离 SQLite 台账聚合与受限 Python 金额解析器修复任务，工具确实执行、有独立正确答案/测试。固定串行/MTP/MTP/串行顺序，分别统计无缓存、大段工具返回及小段前缀复用。失败请求也计入时间与生成量；API 错误时使用单独关联的 reqstat，不能伪称取得了正常 SSE usage。

### 单次错误反馈的补充实验

在首次 `invalid_tool_call` 后只追加一次反馈，要求继续使用已提供的工具名称、参数和格式。其余任务、权重和采样保持不变，上限为 12 轮。这改变了提示词与恢复策略，必须与上面的无反馈正式对照分开解读；它不是 Octop 记忆或配置的修改。

| 模式 | 成功任务 | 实际轮数 | 停止原因 | 加权 Prefill t/s | 加权 Decode t/s | 终止秒 |
|---|---|---|---|---|---|---|
| 串行 | 0/1 | 12 | max_turns | 1205.86 | 23.52 | 165.77 |
| MTP | 0/1 | 12 | max_turns | 1184.51 | 41.03 | 128.99 |

两种模式都跨过了首次协议失败并继续调用工具，但在 12 轮内均未提交结构化结果，各执行 11 次工具调用，其中 2 次工具执行失败。不能将这些失败终止耗时视为交付加速，也不能据此断言给无限轮数仍一定失败。该结果不支持把一次通用重试提示当作可靠的办公修复方案。

## 数值与可用性边界

逐位相同指与同一量化模型、同一既有 grouped/MTP 基线的对照。它不证明量化模型等价于 BF16 权重，也不证明串行与 MTP 对所有随机采样、并发、长上下文、视觉输入都相同。最新旧 w4b/GGUF 的完整回归未在本轮重跑。

启动异常和慢样本不删除：一次组合启动在模型仅加载约 13.9/62.1 GiB 时触发 240 秒上限，清理成功；当时系统提交约 123.4/159.6 GiB，未见提交额度耗尽。此前 9K 组合请求为 43.945 秒，正常基线为 11.990 秒。主 indexer 选核一致；根因未由现有证据确定。单独记录失败启动，完整请求表保留慢样本，重试使用新编号。

本轮没有修改 Windows 电源/驱动设置或部署运行库，也没有借助删慢样本、降低精度或改变模型权重来制造收益。
