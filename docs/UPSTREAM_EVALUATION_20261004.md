# 上游整合评估：2026-10-04

本轮结论：**存在稳定的 Prefill / 首字延迟收益，但真实工具任务的净收益是混合的，不建议据此直接替换日常引擎。** 保留隔离评估分支，适合后续对长输入工作负载继续评估。没有证明工具调用可靠性或通用任务成功率提高。

这里的“稳定”指重复速度测量，不代表数值精度不变。后续 [精度分项与保守配置评估](UPSTREAM_PRECISION_ABLATION_20261004.md) 已验证：关闭新增数值变更项后，可保留约 1.68%–2.01% 的首字延迟收益；被测数值指标、生成和工具行为与旧版一致。

## 实际工具任务

每种任务每版各运行一个固定实例；耗时包括所有模型请求、工具执行与恢复，排除模型加载和结束后的独立评分。没有重跑任务择优。

| 任务 | 版本 | 任务耗时秒 | 模型请求数 | 输出 token | 成功/全部工具调用 | 独立评分 |
|:---|:---|---:|---:|---:|---:|:---|
| 台账 | 基线 | 330.26 | 13 | 13,473 | 20/20 | 通过 |
| 台账 | 候选 | 308.17 | 14 | 10,791 | 16/18 | 通过 |
| 函数修复 | 基线 | 127.50 | 7 | 5,507 | 7/7 | 通过 |

- **台账**：1002 行合成发票/付款，要求全量读取、去重、版本/互斥排除、只读 SQL、整数分金额、分组和逾期 Top5。两版提交均与独立 Python 核验完全一致，交付前独立 SQL 核验也通过。候选耗时减少 **6.69%**，但出现两次 `query_ledger: no such column: c` 后修正；基线没有工具错误。
- **函数修复**：两版都实际读取规则和源码、复现初始故障、修改函数、运行公开测试并提交结果；最终独立 **545/545 隐藏用例通过**。候选多两轮模型请求，输出更多，耗时增加 **9.71%**。公开测试失败记录基线 1 次、候选 2 次，其中包含要求的初始故障复现，不应把这些次数直接等同于工具运行失败。

因此，台账的时间收益和代码任务的时间损失应分别保留。两个固定实例不足以推断总体成功率；任务时间还受到模型规划与生成量变化影响，不能只归因于 Prefill 内核。

## 整合处理

实际解决 5 个冲突文件，并保留本地 22 个独有提交的历史。上游 LUT/v2 内核更新放入 `27_kernels_moe_lut_upstream.inc`、`28_kernels_hgn_v2_upstream.inc`，本地精度内核没有被覆盖。

- 保留 head-interleave、wave norm、aligned MR/GDN/attention、MTP tail 等本地逻辑；新 Dense 和 Write 模板参数单独接入，避免布尔模板位置混淆。
- 对 scratch 缩小加上本地 FP32 专家路径保护，避免把上游内存假设直接套到本地后端。
- 新增 `GDEC_QSA_DENSE_WMMA=0` 退出开关；其余上游选项保留原开关。此次候选启用 FP16 index、FP16 pairs、split-K、Dense WMMA 和有门槛的 MoE multi-tile；HC NORHAT / FUSE_WRITE 保持关闭。
- 缓存 fingerprint 纳入新数值策略与整合版本，避免恢复不同计算策略的旧状态；合入上游恢复 FP16 index twins 的逻辑。
- 适配测试使用正确的 upstream 副本和新增 helper。API/Harness 源码没有因本轮整合改变。

## 采用建议与边界

**保留候选作长输入方向的评估分支；日常引擎暂不切换。** Prefill 收益有重复证据，但解码与完整任务并非全面正收益，工具错误也没有变少。若之后选择采用，应以自己的 Harness 长任务复测作为下一道验收，再决定哪些数值选项默认启用。本轮没有调整量化、MTP gamma 或显存配置去追逐单个结果。

之前 Harness 的工具参数校验错误及错误恢复需求仍需独立处理；本轮没有复现或修复它，也不把 API 测试客户端的恢复机制当成 Harness 已具备该机制。

未覆盖其他模型/量化、其他 gamma、采样分布、SSD checkpoint 持久化往返及真实 Harness UI 多 Agent 工作流。未发布、未部署候选，也没有修改原日常工作区的源码或配置。
