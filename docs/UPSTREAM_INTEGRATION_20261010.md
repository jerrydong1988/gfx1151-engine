## 暂不纳入

- `c83ddfe` PLE flight 重写：当前 Windows 路径已经有 IOCP 预读；本地还有带诊断的 lookahead 与双路让出 GPU 的调度。上游更换缓冲区/线程生命周期并新增一份 pinned staging，并非一个可直接套用的开关。此次未完成新 PLE 实现的独立 A/B，因此不宣称它有或没有收益；保留现有路径，避免将尚未证明的收益带进本轮部署。
- `e2cc188` hipGraph / draft fusion：图捕获路径要求单槽，当前为双槽；算术融合也需要单独的数值验证。本次不改变 GPU 计算路径。
- `04e74f1` 完整模板与 JSON 工具协议：包含默认思考档位、软标签及截断处理等行为变化。格式兼容的有限收益不足以证明应替换当前已验证模板。
- n-gram 默认值和自适应门控：当前使用 MTP，不将不生效的改动混入部署。
- 上游配置面板、托盘遥测、电源统计：不覆盖现有控制台与启动体验。
- TheRock 10.1 默认路径和实验性 v2 权重转换：不升级运行库，不改模型文件或量化；使用与此前相同的 TheRock 10.0。

## 验证方法

以部署目录保存的旧引擎/API 为 A、新构建为 B，使用相同模型、84 项有效运行参数、双槽、
单路 262,144 上下文、524,288 共享 KV、32 图上限，按 A–B–B–A 独立启动。
每轮两次 256/8,192/32,768 token 文本，各生成 128 token；另测 1/16 图。
记录所有请求，包括波动较大的样本，不删除离群值。结果仅适用于这组负载，不等于完整模型能力评测。

构建使用 AMD 官方 TheRock 10.0.0 gfx1151 包，归档 SHA-256 为
`1293927b06b3b8d4bd7e0265823fb998bc9e0d83c68f33dcfa5d32663b30ce38`。
原工具链目录已不存在，本轮恢复到用户缓存，部署目录的运行库不随之替换。

新旧 GPU ELF 的 `.text`（3,476,000 字节）、`.rodata` 和 `.note` 一致。
整个 `.hip_fat` 容器不一致，差异位于符号及字符串/哈希表，因此不声称完整 GPU 容器哈希一致。

可复用测试：

- `tools/upstream_compat_test.cpp`：补边像素不丢失、原图路径不变、预算拒绝、嵌套字面量与转义字符串、必填字段仍拒绝、模板 thinking 状态。
- `tools/template_compat_test.py --baseline <旧 tpl_cli> --candidate <新 tpl_cli>`：796 个既有渲染/错误用例逐字节对照。
- `tools/engine_host_config_test.py --bash <Git Bash> --launcher <新 start_win.exe>`：四种启动入口，含有效子进程环境和 YaRN 边界。
- `tools/api_capacity_health_test.py --api <新 API>`：新旧 INFO 协议容量协商。
- 既有工具参数诊断、图像总预算、API 协议、断连/排队/取消恢复测试。

- 普通图片、字面量、模板状态与既有工具/视觉单元检查共 180 个断言通过。

- 启动配置 75 项、新旧容量协商 3 项、完整 API 协议 90 项、工具错误诊断 458 项、断连/排队恢复 49 项及取消超时恢复检查通过。
- 24 个主对比文本请求与 12 个专项复测文本请求，同输入的输出 token 序列集合一致；这不是全模型精度基准。
- 32 图全部可见编码识别、16+4 历史图片、33 图拒绝与拒绝后恢复通过。
- 1200×5、4×900、2000×5 图片真实模型请求均成功。

- 控制台在真实候选服务上显示单路 262,144、KV 总容量 524,288、32 图；无浏览器脚本错误。
- 相同工作负载（主对比 A1/B1/A2）的设备当前/峰值分配及 pinned 当前/峰值分配一致。B2 额外运行了 32 图扩容测试，其缓存占用不与 16 图负载混比。
